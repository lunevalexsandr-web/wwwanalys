# wwwanalys — функциональность приложения

Лабораторная система пивоваренного завода: учёт анализов, контроль отклонений,
интеграция с 1С:ERP, AI-агент «эксперт-пивовар», планирование и ежедневная сводка.

- **Бэкенд:** FastAPI + SQLAlchemy + PostgreSQL (pgvector).
- **Фронтенд:** React + TypeScript + React-Bootstrap (production-сборка nginx).
- **Развёртывание:** Docker Compose (ВМ 10.40.100.50), образы `las84/wwwanalys-{backend,frontend}`.
- **Интеграция:** 1С:ERP по OData, база `erp_24` (`/erp_24/odata/standard.odata`).
- **Время:** расписания и сводка работают по **МСК (UTC+3)**.

---

## 1. Отчёты и показатели

- **Отчёты (ProcessLog)** — результаты анализов партии: сорт, тара/цех, партия, набор
  показателей (IndicatorValue) по шаблону.
- **Справочник показателей (IndicatorLibrary)** — числовые/текстовые/select-показатели,
  единицы измерения, категории, нормы.
- **Шаблоны анализов (AnalysisType)** — наборы показателей; нормы задаются матрицей
  день × сорт × тара (TemplateNorm) с фолбэком на TemplateIndicator.
- **Движок отклонений** (без модели): сравнение с нормой (min/max) для чисел и по эталону
  (norm_text) для текст/select. Отклонения помечаются флагом `is_normal=false`.
- **История отчётов:** фильтры, подсветка строк с отклонениями (`table-warning` + `⚠ N`),
  фильтр «только с отклонениями».

## 2. Аналитика

- Сводная аналитика за период: доля отклонений, по дням, по шаблонам, топ показателей,
  список отклонений (партия, показатель, значение, норма).
- Кнопка экспертного разбора периода (нужна подключённая модель).

## 3. AI-агент «эксперт-пивовар»

Провайдеры (выбор по наличию ключа): **OpenRouter** (OpenAI-совместимый,
модель `openai/gpt-4.1-mini`) → иначе **Anthropic** (Tool Runner). Модуль изолирован:
при отсутствии ключа работает режим «только факты».

**Режимы:**
- **Разбор отчёта** — по кнопке в отчёте: трактовка отклонений, вероятные причины,
  корректирующие действия (с опорой на RAG-техкарты).
- **Разбор периода** — нарратив по сводке (причины сгруппированы по типу проблемы;
  перечень отклонений идёт отдельной таблицей, не дублируется).
- **Чат с агентом** (стр. «🤖 Агент» и чат внутри «Сводки») — вопросы по данным
  анализов, отклонениям, санитарии, плану. Формат ответа: по умолчанию «📌 Кратко»,
  «Подробно» — только по явному запросу.

**Инструменты агента (function-calling):**
- `get_deviations_by_date` — отклонения за день;
- `get_period_summary` — сводка за период;
- `get_report_deviations` — отклонения по партии;
- `get_release_status` — допуск/недопуск партий за день + по каким показателям недопуск;
- `get_sanitation` — выполненные санитарные мероприятия за период/линию;
- `get_sanitation_schedule` — справочник мероприятий с требуемой частотой;
- `get_sanitation_compliance` — какие мойки просрочены/не выполнены на дату;
- `get_sanitation_plan` — план санитарии на день (просроченные + плановые);
- `search_tech_cards` — RAG-поиск во внутренних техкартах.

Для микробиологических отклонений в цехах розлива (КЕГ / Стекло=«PALI» /
Стекло_2=«Krones») агент сверяется с санитарией и соблюдением её периодичности.

**Главный рубильник агентов** (⚙️ Настройки → 🤖 Агенты): один переключатель
останавливает/запускает все агенты (чат, разбор, дежурный агент, планировщик санитарии).
Хранится в БД, без перезапуска. Управление — только администратор.

## 4. Ежедневная сводка «дежурного агента» (стр. «📅 Сводка»)

Автоматически по расписанию (МСК) или по кнопке «Сформировать сейчас».

- **Автоимпорт из 1С за последние 3 дня** (результаты анализов + санитария) — закрывает
  пробелы, идемпотентно.
- **Пункт 1 — таблица отклонений в отчётах:** партия, сорт, **ёмкость** (танк из
  показателей: «Ф 13», «ЦКТ 48»…), цех, показатель, значение, норма, отклонение (%).
  Метка партии: нормальный номер — как есть; иначе «сорт · ёмкость»; иначе «#id».
- **KPI:** допущено, не допущено, санитария просрочена.
- **Разбор агента** — причины и корректирующие действия (по группам проблем).
- **Допущенные / Не допущенные партии** — по показателю «Допуск к розливу»; для
  недопущенных выводятся **все** показатели-причины (значение + норма).
- **Санитария — просрочено/не выполнено** (см. п.5).
- **Чат по сводке** — агент отвечает в контексте текущего дня (дата, отклонения с
  ёмкостями, недопуск, санитария).

**Расписание** (⚙️ Настройки → 🤖 Агенты): вкл/выкл автозапуска, время (МСК), за какой
день (вчера/сегодня). Фоновый поток проверяет расписание раз в минуту.

## 5. Санитария

- **Импорт из 1С:** выполненные мероприятия (регистр `_ОтчётПоСменеСанитарныеМероприятия`)
  + справочник `_СанитарныеМероприятия` с частотой (УсловияНаступленияМероприятия,
  ИнтервалВЧасах). Тара отчёта привязана к линиям розлива.
- **Справочник мероприятий** — в разделе «Справочники»; **журнал выполненных** — в «Аналитике».
- **Планировщик санитарии** (`sanitation_planner`): по периодичности (интервал в часах или
  текст «1 раз в неделю», «каждые 12 часов»…) и дате последнего выполнения считает
  следующий срок → выявляет **просроченные / ни разу не выполненные**. Событийные
  («каждый CIP», «каждые N часов работы») в календарь не ставятся.
- **Страница «🧼 План»** (`/sanitation-plan`): план на день (просроченные + плановые),
  выбор даты (МСК) и горизонта (сегодня/+3/+7/+14), KPI.

## 6. Планирование анализов (раздел «Планирование»)

- **Наши планы (AnalysisPlan/PlanItem)** — планы на дату для лаборантов: задачи (шаблон +
  партия), отметки о выполнении, создание отчёта из задачи.
- **План из 1С** — интеграция с готовым механизмом 1С:
  - справочник `_ОбъектыКонтроляДляПланированияАнализов` (объект контроля → типовой анализ →
    периодичность), регистр `_ПланированиеЛабораторныхАнализов` (план вперёд + статус).
  - **Вкладка «📋 План из 1С»** — таблица плана за дату (объект контроля, типовой анализ,
    партия, сорт, периодичность, статус), счётчики Всего/Выполнено/Ожидают, фильтр
    «только не выполненные». Данные подгружаются автоматически при открытии (авто-импорт,
    если за дату их ещё нет).
  - **Кнопка «📥 Новый план из 1С»** — создаёт/пересобирает наш План «План из 1С» на дату:
    каждая запись 1С (типовой анализ → наш шаблон по GUID, партия из серии, статус из 1С)
    становится задачей плана. Дедуп по шаблон+партия.

  > По периодичности анализов: ~90% объектов — **событийные** (КаждаяПартия и
  > производственные события), их планирует сама 1С (регистр заполнен наперёд).
  > Наша роль — импорт готового плана 1С и контроль выполнения.

## 7. Интеграция с 1С (ODATA, база erp_24)

- Импорт: показатели, шаблоны, нормы, сорта, объекты, варианты хранения/значений,
  результаты анализов (документ `УстановкаАнализовСерии`), санитария, план анализов.
- Резолв ссылок GUID → наименование (склады, доп.аналитика, серии, номенклатура, линии,
  подразделения, сотрудники/физлица).
- Идемпотентность по `external_id` (GUID документа или md5 составного ключа).
- Внешний IP подключения к 1С (для белого списка): **88.99.96.160**.

## 8. Разделы интерфейса

- **Панель управления** — отчёты, история, создание/редактирование.
- **Планирование** — планы на дату + План из 1С.
- **Аналитика** — сводная аналитика + журнал санитарии.
- **🤖 Агент** — чат с агентом.
- **📅 Сводка** — ежедневная сводка.
- **🧼 План** — план санитарных мероприятий.
- **Справочники** — шаблоны, показатели, сорта, объекты, санитарные мероприятия.
- **База знаний** — техкарты (RAG).
- **⚙️ Настройки** — Агенты (рубильник + расписание), Пользователи, Интеграция с 1С.
